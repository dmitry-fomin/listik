# Autopilot против конвейеров Listik — сравнение, 27.10.2026

Сравниваются:

- **autopilot** — `nick-vels/skills/skills/autopilot`, версия 2.2.0: `SKILL.md`, `phases/*`,
  `prompts/*` (HTML-дашборд и тело `tools/ap.py` не читались);
- **listik-pipeline** — `plugins/listik-pipeline`, версия 0.2.0;
- **pipeline-full + pipeline-core** — `plugins/pipeline-full` (пресеты) и `plugins/pipeline-core`
  (ядро `references/pipeline-core*.md`, агенты `pipeline-*`).

Вопрос: чего не хватает нашим скилам, чтобы, как autopilot, за один проход собрать большую
функциональность.

## Итог

| | autopilot | listik-pipeline | pipeline-full + core |
|---|---|---|---|
| Единица работы | прогон: бриф → N тикетов | одна карточка, один исполнитель | шаг → порции (эпик → дочерние карточки) |
| Нарезка на части | да, по объёму (≈3K строк на тикет), ярусы T0–T3 | **нет** | да, но без калибровки размера |
| Параллель частей | волны по графу зависимостей, до 3 исполнителей | нет | **только треки**, названные автором; порции внутри трека строго по очереди |
| Трассировка требований от брифа | манифест `R##` с цитатами, `check-plan` | нет | нет |
| Проверка покрытия брифа (G2) | независимый читатель: бриф + спека | нет | нет (критик судит порцию «в её границах») |
| Критика ТЗ | нет | 1–3 критика разных моделей | 3 критика с кворумом на **каждую** порцию |
| Приёмка части | точечное ревью только фундамента и рисков | линза → судья по риску | линзы Haiku → судья другой модели |
| Ревью всей ветки | да, один раз в конце, находки в тикет `F1` | нет | нет |
| Слепая приёмка с запуском (G4) | да: чистый клон, запуск, сценарий против брифа | нет | нет |
| Пересмотр плана по ходу | `D##`: правка спеки + перенарезка затронутого | стоп | «полный круг» — только текущая порция |
| Изоляция | одно дерево, зоны | `listik worktree` | дерево на трек |
| Модели | только Claude (сильная/обычная) | Claude + pi/grok/codex/devin | Claude + pi/grok/codex/devin/dsh |
| Состояние, возобновление | `.autopilot/state.js`, `0-resume.md` | карточка Listik, процедуры нет | журнал шага + карточки, процедура есть |
| Итог для человека | отчёт, `PROGRESS.md`, ADR, память | `done -r "коммит …"` | `done` эпика |

Коротко:

- **listik-pipeline** — конвейер одной задачи. Для большой фичи ему не хватает почти всего
  из колонки autopilot, прежде всего нарезки.
- **pipeline-full + core** — это фазы 3–5 автопилота (спека → нарезка → сборка), с более
  сильной проверкой каждой порции. Не хватает начала (манифест, брифинг), конца (ревью ветки,
  слепая приёмка) и параллели порций.

## Как устроен autopilot

Порядок фаз — продукт: код пишется в предпоследней фазе.

| Фаза | Что делает |
|---|---|
| 0 Preflight | режим участия (`full`/`semi`/`interview`/`manual`) и глубина (`strict`/normal/`deep`), git, память проекта, дашборд, `carried.md` из прошлого прогона |
| 1 Manifest | бриф дословно в файл (только дописывается в «Дополнения»), маскировка секретов, атомизация в требования `R##` с цитатами |
| 2 Briefing | вопросы раундами до 4, у каждого рекомендация; блокирующие внешние вещи в первом раунде; adversarial-проход из 7 вопросов при `deep`/`interview` |
| 3 Spec | разведка кода субагентом в `notes.md`; проработка вглубь по 8 измерениям (первый запуск, пусто, неверный ввод, сбой, прерывание, рост, права, последствия); границы модулей в `interfaces.md`; гейт G2 |
| 4 Plan | оценка объёма в строках → ярус и число тикетов; зоны, зависимости, волны; проход склейки; expand → migrate → contract для широких правок; `check-plan` (G3); коммит плана |
| 5 Build | один тикет — один субагент в свежем контексте; волна одним сообщением, до 3 параллельно; контракт возврата ≤25 строк; коммит на тикет с trailer'ами |
| 5 Repair | недоделка → дозапрос в ту же сессию; отказ → свежий контекст на сильной модели; по 2 ремонта и ретрая; «сборка опровергла план» → `D##` |
| 6 Review | точечное ревью только фундамента и рисков, после коммита и без остановки волны; ревью всей ветки в конце, «чинить сейчас» → тикет `F1` |
| 8 Final | слепая приёмка (G4): только бриф, чистый клон, запуск; ADR; память; отчёт из файлов, не из памяти; `PROGRESS.md` |

Пять правил, которые не обсуждаются: требование снимает только пользователь; секрет никогда
не запрашивается и не пишется; факт о пользователе не выдумывается (только видимая заглушка);
необратимое действие — всегда вопрос; оркестратор не пишет код проекта.

## listik-pipeline против autopilot

### Чего не хватает (по убыванию важности)

1. **Нарезки нет.** Одна карточка: одно ТЗ, один исполнитель. На большой фиче исполнитель
   упрётся в свой контекст.
2. **Нет `interfaces.md`.** С одним исполнителем он не нужен; с несколькими первый решит
   архитектуру, увидев малую часть задачи.
3. **Нет трассировки требований.** Линза и судья сверяют код с ТЗ, то есть с пересказом
   писателя. Требование, потерянное писателем, никто не заметит. У autopilot это закрывают
   дословный бриф, манифест, G2 и G4.
4. **Нет пересмотра плана.** Два `CANNOT` или три захода судьи без `PASS` — стоп. Различия
   «недоделка/отказ» и `D##` нет.
5. **Нет ревью всей ветки** и проверки того, как части работают вместе.
6. **Нет брифинга до спеки.** `QUESTION` по одному, каждый останавливает конвейер.
7. **Нет проработки вглубь** по измерениям в `writer.md`.
8. **Контракт исполнителя слабее.** `DONE` + вывод проверки; нет `REDPROOF`,
   `INTERFACES`, `REQUIREMENTS`.
9. **Нет процедуры продолжения** после обрыва сессии на `s3-impl`.

### Что сильнее

Критики и судьи на других моделях; worktree и `merge --ff-only`; критика ТЗ до кода;
внешний трекер с доской и `needs-owner`; флаг риска экономит судью.

## pipeline-full + pipeline-core против autopilot

### Что совпадает

| autopilot | pipeline-full / core |
|---|---|
| спека → тикеты `NN-*.md` | шаг `<id>.md` → порции `<id>.<X>.md` с чек-листами `check-<X>` |
| тикет — то, что один исполнитель делает в свежем контексте | «порция — то, что один исполнитель делает за один заход без переписки; крупный шаг — больше порций, а не крупнее порции» (`pipeline-spec-writer.md`) |
| исполнитель получает пути, тикет самодостаточен | исполнитель получает **только файл порции** |
| зона тикета | «Границы правки», счётчик `V`, находки `ГРАНИЦЫ:` |
| тикеты в state.js | эпик → дочерние карточки `listik new … --parent` |
| брифинг раундами с рекомендацией | вопросы писателя «все разом» с «предпочитаю», `AskUserQuestion` до 4 |
| режим `full`: `ASSUMPTION` | headless: берётся предпочтённый вариант, `needs-owner` с «по умолчанию: …» |
| `REDPROOF` | негативный контроль (только для гардов и проверок) |
| `Ревью: да — риск` | `## Критичные инварианты` делают судью обязательным |
| пределы на ремонт и ретраи | счётчики `M`/`K`/`V`, «полный круг» |
| продолжение по `state.js` | продолжение по журналу шага после `/clear` |
| оркестратор передаёт пути | то же + «копия, а не пересказ» |

### Чего не хватает

1. **Порции не идут параллельно.** Ядро: «в одном дереве — одна пишущая порция кода…
   параллелить порции внутри трека нельзя». Параллель — только треки, и только те, которые
   автор назвал независимыми (`pipeline-core-tracks.md`). У порции нет поля «зависит от»:
   порядок задан буквами `a, b, c`, связи `blocks` между карточками порций не ставятся.
   Восемь порций — восемь полных циклов подряд (критика, код, линзы, судья).
2. **Размер порции не откалиброван.** Нет оценки объёма в строках, ярусов и прохода склейки.
   Слишком мелкую нарезку никто не поймает, а каждая порция — это холодный старт исполнителя
   и отдельная критика.
3. **Нет `interfaces.md`.** При последовательных порциях терпимо: следующий исполнитель
   читает закоммиченный код. При параллели файл становится обязательным.
4. **Нет сверки с исходной задачей.** Критик: «порцию судишь в её границах: то, что вынесено
   в другую порцию шага, — не замечание». Никто не проверяет, что сумма порций покрывает
   задачу, а именно здесь autopilot ловит потери (G2).
5. **Нет финала.** После последней порции — `listik done <эпик>`. Нет ревью всей ветки,
   нет слепой приёмки с запуском. В треках прямо сказано: «зелёное **не** значит, что
   интеграция сделана — она отдельная задача автора».
6. **Изменение плана не доходит до следующих порций.** «Полный круг» переписывает ТЗ
   только текущей порции. Уже написанные следующие порции не пересматриваются.
7. **Нет проработки вглубь и adversarial-прохода.** Писатель спрашивает, только если без
   ответа выбирал бы между двумя разными ТЗ.

### Что сильнее

- Критика каждой порции тремя моделями с кворумом. У autopilot критики спеки нет, есть
  только проверка покрытия.
- Линзы плюс судья другой модели. У autopilot все проверяющие — Claude.
- Отдельное дерево на трек. Autopilot пускает параллельных исполнителей в одно дерево.
- Предполёт UI, живые сценарии, «копия из вывода», запись живых проверок.
- Headless-режим под роем.

## Что добавить

Брать из autopilot выборочно. Дашборд, `ap.py`, режимы участия, ADR и память не нужны:
их роль закрывают доска Listik, журнал и `needs-owner`.

| # | Что | Куда | Закрывает |
|---|---|---|---|
| 1 | Финальный этап после последней порции: ревью всей ветки от базы эпика + слепая приёмка против исходной задачи (чистый клон, запуск, сценарий; спеку и порции не давать) | новая часть ядра, два субагента | пункт 5 |
| 2 | Проверка покрытия после этапа 1: субагент читает только спеку или текст автора и `<id>.md` со списком порций и ищет, что потеряно или покрыто наполовину | ядро, этап 1 | пункт 4 |
| 3 | Параллель порций: писатель пишет у порции «зависит от» и оценку объёма; оркестратор ставит `dep add … blocks` между карточками порций, независимые запускает в своих деревьях механикой треков (`listik worktree --track`, `merge --no-ff`); при параллели — `interfaces.md` шага | писатель, ядро, треки | пункты 1–3 |
| 4 | Пересмотр следующих порций, когда реализация опровергла план шага | ядро, «Пределы на порцию» | пункт 6 |
| 5 | Рамка проработки вглубь (8 измерений) в писателе | `pipeline-spec-writer*.md` | пункт 7 |

Пункты 1–2 дешёвые и закрывают самую большую дыру: сейчас ничто не проверяет, что собранное
целиком соответствует задаче. Пункт 3 даёт скорость на большой фиче. Пункты 4–5 стоит
отложить, пока нет 1–3.

**Не проверено:** по `docs/API.md` Listik уже умеет нарезку для маршрутов роя
(`kind=swarm`): `suggested-blocks` между порциями родителя превращаются в жёсткие `blocks`,
у роя есть `--parallel` и барьер волны. Пресеты `pipeline-full` этот путь не используют, и
пойдут ли порции эпика роем параллельно, не проверялось. Это может оказаться самым дешёвым
способом сделать пункт 3.
