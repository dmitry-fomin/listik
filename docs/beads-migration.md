# Переход проекта с beads на Listik

Задачи больше не ведутся в `.beads`. Трекер один — Listik, он живёт в `~/Projects/Listik/hub`.
Каталог `.beads` в проекте можно оставить как архив: он больше не читается и не обновляется.

## Что сделать в проекте

1. **Убрать из `AGENTS.md` / `CLAUDE.md` инструкции про `bd`.** Минимум — добавить блок ниже.
   Пока старые инструкции на месте, агент будет писать задачи в мёртвый трекер, и на доске
   их не будет видно.

2. **Выключить авто-экспорт и хуки beads** (иначе репозиторий продолжит коммитить
   `.beads/issues.jsonl` и дёргать `bd` в pre-commit):

   ```sh
   cd <проект>
   sed -i '' 's/^export\.auto:.*/export.auto: false/' .beads/config.yaml   # если ключ есть
   bd hooks uninstall 2>/dev/null || true
   ```

   Сам `bd` не удаляем: он нужен, если понадобится поднять старую историю.

3. **Проверить свои git-хуки**, если они ссылались на `bd` (например, «закоммитил — закрой
   задачу»). Договорённость теперь такая: агент сам делает `listik done`, а не хук.

## Блок для `AGENTS.md` проекта

```md
## Трекер задач — Listik (не beads)

Задачи этого проекта ведутся в Listik: `~/Projects/Listik/bin/listik`.
`.beads` — архив, писать туда нельзя.

- Обстановка по всем проектам: `~/Projects/Listik/bin/listik board`
- Взял в работу: `listik claim <id> --holder <кто>` (без claim задача «никем не держится»)
- Работаешь дольше 10 минут: `listik heartbeat <id> --holder <кто> --note "что делаю"`
  (без heartbeat через 24 ч задача помечается брошенной)
- Перешёл на следующий этап: `listik stage <id> --holder <кто>`
- Вопрос к человеку: `listik needs-owner <id> "вопрос"`
- Закрыл: `listik done <id> -r "результат"`
- Прежде чем проектировать: `listik search "<суть задачи>"` — искать по всей истории задач
  и по памяти, решение могло быть найдено в другом проекте.

Полные правила: `~/Projects/Listik/AGENTS.md`, контракт данных — `API.md`.
```

## Что делать с задачами, которые были в `.beads` проекта

Они уже импортированы в Listik (`source=beads`, прежний ID в `external_ref`), привязка
к проекту сохранилась. Отдельно переносить ничего не нужно:

```sh
cd ~/Projects/Listik/hub
./bin/listik list --project <slug> --all      # проверить, что задачи на месте
```

Название проекта в Listik — относительный путь от `~/Projects`, например
`Zoloto585/zoloto585-search` или `Dif/Server`. Полный список: `./bin/listik projects`.

## Если трекер в проекте вообще не нужен

Ничего не делай: задачи останутся в Listik с пометкой проекта, а проект можно скрыть —
`archived=1` в таблице `projects` (появится команда, если понадобится).
