# Шаг 01. Документы, чанки и контекст

## Цель

Сделать Markdown-ТЗ первоклассным индексируемым источником, не помещая весь файл в каждую
карточку и не ломая существующие FTS/embedding-поиск.

## Требования

1. Добавить миграции для `documents` и `document_chunks` с внешним ключом на `tasks`.
2. Индексировать `spec_path`, acceptance/checklist path, review и decision-файлы явно.
3. Строить чанки по Markdown-заголовкам, сохраняя `heading`, `breadcrumb`, строки начала/конца.
4. Для раздела больше лимита резать по абзацам/спискам, добавляя overlap, но не дублировать
   один и тот же чанк при повторном запуске.
5. Использовать `content_hash` и `revision`, чтобы неизменённый документ не пересчитывался.
6. Перенести FTS и embedding на уровень чанков с обратной совместимостью поиска задач.
7. Добавить CLI/API `context`; JSON должен содержать задачу, документы, chunks, лимиты и причину
   включения каждого блока.

## Контракт context

`--stage s1`: карточка, полный spec, checklist, список зависимостей.

`--stage s2`: всё из s1 плюс предыдущие review; ограничение применяется только к очень большим
файлам и явно отражается в ответе.

`--stage s3`: краткая карточка, выбранная порция, acceptance, подтверждённые зависимости,
последний review и релевантные chunks.

`--stage s4`: diff/worktree metadata, acceptance, review, journal transitions, verdict и
релевантные chunks; исходный spec берётся по ссылке и только нужными разделами.

## Критерии приёмки

* Повторная индексация одинакового файла не создаёт новых документов/chunks.
* Поиск по фразе, встречающейся только в середине длинного раздела, находит задачу и показывает
  заголовок/breadcrumb.
* Удалённый или недоступный файл даёт диагностическое событие, но не ломает `listik show`.
* `context --format json` стабилен для автоматического вызова harness.
* Старые `search` и `show` продолжают работать для задач без документов.

## Не делать на этом шаге

Не менять алгоритм RRF без необходимости, не делать автоматический пересказ ТЗ моделью и не
вводить отдельную векторную базу. SQLite/существующий embedding worker достаточно.
