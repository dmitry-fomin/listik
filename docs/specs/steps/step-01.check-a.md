# Приёмка порции 01.a. Тестовый каркас и правки чанкера

Все команды — из корня репозитория. Тесты не должны требовать сервера и Ollama.

## Каркас

1. `python3 -m unittest discover tests -v` завершается кодом 0 и выводит не меньше двух
   тестовых модулей: `test_chunking` и `test_index_documents`.
2. В `tests/fixtures/` лежат `long-spec.md` (>= 25 000 символов, `wc -c`), `lists.md`,
   `fenced.md`, `checklist.md`. В `long-spec.md` есть раздел `##` длиннее 15 000 символов и
   уникальная фраза в его середине, встречающаяся в фикстурах ровно один раз (`grep -c`).
3. После прогона тестов `git status` не показывает изменений в `listik.db`, `listik.log`,
   `listik.pid`, и в корне не появилось новых `.db`-файлов.
4. `CLAUDE.md` содержит команду `python3 -m unittest discover tests` и больше не утверждает,
   что тестового набора нет. Другие разделы файла не изменены (проверяется `git diff CLAUDE.md`).

## Чанкер (тесты, которые падают до правки и проходят после)

Базовая ревизия для «до правки» — коммит `b757cf6`. Доказательство красного прогона —
обязанность исполнителя: в журнале задачи (`comment -k journal`) и в отчёте лежит хвост
вывода `python3 -m unittest tests.test_chunking -v`, выполненного в отдельном рабочем дереве
`git worktree add /tmp/listik-base b757cf6` с скопированным туда каталогом `tests/`. Судья
сверяет журнал; при сомнении повторяет ту же процедуру сам (обязательно с
`git worktree remove --force` после) — `git show HEAD:…` во временный файл не использовать:
после коммита порции `HEAD` уже новый, а модуль с относительными импортами вне пакета не
импортируется.

5. Code-fence: в журнале красного прогона тест `fenced` в статусе `FAIL`; на текущем коде
   тест `fenced` в `test_chunking` зелёный, и
   `documents.split_markdown("# a\n\n```\n# not heading\n```\n\n## b\n\nтекст")` возвращает
   чанки только с `heading` `a` и `b`.
6. Списки: в журнале красного прогона тест `lists` в статусе `FAIL`; на текущем коде для
   `lists.md` каждый чанк после префикса breadcrumb начинается с маркера списка, ни один пункт
   не разрезан посередине, и первая строка чанка N+1 не встречается в чанке N (overlap между
   группами пунктов отсутствует).
6а. Переполнение на overlap-хвосте: в журнале красного прогона тест «переполнение на хвосте»
   в статусе `FAIL` (на базовой ревизии чанк доходит до `MAX_CHARS + 242`); на текущем коде
   `len(text) <= MAX_CHARS` для всех чанков этого теста.
7. `documents.split_markdown` существует и `documents._split_markdown is documents.split_markdown`
   (или алиас вызывает её) — существующие вызовы не сломаны.
7а. После проверки в `.git/worktrees` нет записи `listik-base` (`git worktree list` показывает
   только основное дерево).

## Свойства резки (тесты)

8. Для `long-spec.md`: у каждого чанка `text.startswith(breadcrumb)`, `1 <= start_line <= end_line
   <= N`, `len(text) <= 6000`; раздел > 15 000 символов даёт >= 3 чанков; уникальная фраза
   найдена в чанке с `heading` этого раздела; в этом разделе существует хотя бы одна пара
   соседних чанков N, N+1, у которой последние `OVERLAP` символов текста N (без префикса
   breadcrumb) встречаются в начале текста N+1 (после префикса) — политика overlap из §2 ТЗ:
   гарантия «хотя бы одна пара», а не «все соседние».
9. Два вызова `split_markdown` на одном тексте равны (`assertEqual` списков словарей).

## Идемпотентность индексации (тесты на временной базе)

10. Повторный `index_document` того же файла: количество строк в `documents`,
    `document_chunks`, `document_chunk_fts` не меняется, `revision` = 1, `updated_at` тот же,
    событий `document_error` нет.
11. После дописывания раздела: `revision` = 2, чанков стало больше, в `document_chunk_fts` нет
    `chunk_id`, отсутствующих в `document_chunks`. После укорачивания файла — нет сиротских
    ordinal ни в одной из двух таблиц.
12. `store.create_task(..., spec_path=…, checklist_path=…)` создаёт две строки `documents`
    с `kind` `spec` и `checklist`.

## Границы

13. `git diff --stat HEAD` показывает изменения только в `listik/documents.py`, `CLAUDE.md`
    и `tests/**`. `listik/db.py`, `alembic/`, `search.py`, `embed.py`, `server.py`,
    `client.py`, `bin/listik` не изменены.
14. `MAX_CHARS`, `OVERLAP`, формат `id` чанков `<doc_id>:<ordinal>` и функция
    `documents.context` не изменены (проверяется чтением диффа).
