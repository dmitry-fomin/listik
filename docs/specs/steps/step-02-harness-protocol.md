# Шаг 02. Общая инструкция для harnesses

## Цель

Дать Claude, Codex, dsh, Grok и WriterLLM одинаковый короткий протокол, чтобы карточка была
продолжаемой после закрытия сессии. Этот текст пользователь сможет целиком добавить в WriterLLM
и адаптированные AGENTS.md других проектов.

## Текст инструкции

```text
Listik — единственная очередь и журнал работы. Перед началом:
1. Выполни `listik ready` и `listik search`, затем `listik show <id>`.
2. Не бери заблокированную задачу. Если блокер брошен, возьми блокер или поставь ему needs-owner.
3. Взяв задачу, сразу сделай `claim <id> --holder <твой-harness>`.
4. Работая дольше 10 минут, делай heartbeat каждые 10–15 минут с короткой заметкой.
5. При переходе этапа используй `stage`; не подменяй переход изменением текста карточки.
6. Замечания пиши `comment -k review`, решения и ход работы — `comment -k journal`, вердикт —
   `comment -k verdict`.
7. Вопрос человеку оформляй `needs-owner <id> "точный вопрос"`; не оставляй его только в чате.
8. Перед handoff проверь spec_path, acceptance, worktree/branch, зависимости и журнал.
9. Завершая работу, выполни `done <id> -r "краткий проверяемый результат"`.
10. Чужую карточку не переписывай: добавь comment и сообщи о проблеме через Listik.
```

## Адаптация по роли

* `s1`: создать/обновить Markdown-ТЗ, acceptance, дочерние порции и предложения зависимостей.
* `s2`: критик проверяет полноту и реализуемость, не пишет код и оставляет review.
* `s3`: исполнитель читает `context`, меняет код, запускает проверки и оставляет journal.
* `s4`: судья проверяет acceptance и diff, пишет verdict; коммитит только при зелёном результате.

## Критерии приёмки

* Инструкция помещается в один блок AGENTS.md без ссылок на конкретный harness.
* Для каждого этапа явно указано, что читать, что изменять и какой переход выполнять.
* Вопрос, heartbeat и handoff можно восстановить только по Listik без истории чата.
