# Шаг 03. Импорт старых задач WriterLLM

## Цель

Перенести существующие задачи WriterLLM в Listik без потери истории и без риска создать
дубликаты при повторном запуске.

## Требования

1. Определить входной формат (экспорт WriterLLM, каталог Markdown/JSON или оба) и реализовать
   адаптеры с единым внутренним record.
2. Команда `listik import-writerllm --source <path> [--project <slug>] --dry-run` показывает
   количество create/update/skip/error и первые примеры.
3. Ключ идемпотентности: source system + project + `external_ref` (старый ID); при отсутствии
   ID использовать стабильный hash нормализованного пути и заголовка.
4. Сохранить старые ID, названия, описания, acceptance, статусы, приоритет, timestamps,
   holder, зависимости, результаты и пути журналов.
5. При повторном импорте существующая карточка не перезаписывается молча: default `skip`,
   явный `--update` создаёт diff/журнал.
6. Ошибка одной записи не останавливает импорт; итоговый отчёт пригоден для CI и содержит
   ненормализованные записи.

## Критерии приёмки

* Dry-run не изменяет БД.
* Два одинаковых запуска дают одинаковое число новых задач (второй — ноль).
* Связи импортируются после задач и ссылаются на новые Listik IDs.
* Старый ID находится через `search`, `show` и `external_ref`.
* Импорт не стирает уже существующий ручной комментарий.
