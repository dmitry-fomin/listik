## Форма

4. Кнопка «Новая задача» на доске открывает `UiModal` (размер `lg`, ширина ≤ 760px) с заголовком
   «Новая задача» и подсказкой «что делаем, в каком проекте и как: кто исполняет и по какому
   процессу»; в подвале — «Отмена» и «Создать задачу» (тип по умолчанию `task`).
5. Первая строка — три `UiField`: «Тип» (`UiSegmented`: «эпик · ТЗ», «задача», «баг»; слева от
   сегмента глиф выбранного типа меняется вместе с выбором), «Проект» (`UiSelect` с опциями из
   `/api/meta.projects`, слева метка-монограмма выбранного), «Приоритет» (`UiSegmented`).
6. Приоритет: при типе «задача»/«эпик» опции `P1…P4`, подсказка «P0 — только для багов»; при «баг»
   появляется `P0` первой; выбрать «баг» → `P0` → сменить тип на «задача» → выбрано `P1`. Под
   сегментом — глиф и слово выбранного приоритета («обычный» для P2). **Красный до правки**: приоритет
   вводится текстом.
7. «Заголовок» обязателен: кнопка создания `disabled` при пустом заголовке или невыбранном
   проекте; после клика с пустым заголовком (если кнопка доступна иным путём) — `error` «нужен
   заголовок» у поля. «Описание · ТЗ» — `UiTextarea` с подсказкой «markdown · эпик режется на шаги
   и порции на этапе s1, здесь только суть»; «Критерии приёмки» — `UiTextarea`; «Путь к ТЗ
   (spec_path)» — `UiInput` с плейсхолдером `docs/specs/….md`. Отдельного поля «декомпозиция» нет.

## Отправка

14. Мок **не обрабатывает** `POST /api/tasks` (отвечает 200 со списком задач) и в `MOCK_LOG`
    печатает только метод и путь без тела — успех на моке ничего не доказывает. Поэтому на моке
    проверяется только состав запроса, снятый в браузере: DevTools → Network → `tasks` → Request
    Payload (или разовая обёртка `fetch` через `Runtime.evaluate`): при создании «баг», P0, проект
    `listik`, описание, критерии, `spec_path`, маршрут dsh × прямая — метод `POST`, путь
    `/api/tasks`, тело ровно `{title, project:'listik', type:'bug', priority:0, description,
    acceptance, spec_path, labels:['harness:dsh','process:direct'], actor:'me'}`; ключей
    `harness`/`skill`/`process` нет; при пустом поле `spec_path` ключа `spec_path` в теле нет.
    «Отмена» и `Escape` закрывают окно без запроса `POST /api/tasks` (в Network запроса нет).
    Тост «Задача создана», закрытие окна и сброс формы (повторное открытие — тип «задача», P2,
    claude × feature, пустые поля) на моке фиксируются, но доказательством отправки не считаются.
15. Живой сервер (временная база, `serve --port 8797`) — единственная проверка результата:
    после создания той же задачи `./bin/listik --local show <id> --json` (с тем же `LISTIK_DB`)
    показывает `issue_type: "bug"`, `priority: 0`, `acceptance` и `description` с введённым
    текстом, `spec_path` с введённым путём, `labels` ровно `["harness:dsh", "process:direct"]`
    (две метки, ничего лишнего); задача, созданная с пустым `spec_path`, имеет `spec_path: null`
    (не `""`); карточка появляется в колонке «Заведена» (без этапа), в панели метки видны бейджами;
    тост «Задача создана», окно закрыто. **Красный до правки**: старая модалка не шлёт `labels`,
    `acceptance`, `spec_path`, а `type`/`priority` берёт из текстовых полей.
16. Ошибка сервера (остановить мок перед отправкой или создать с несуществующим проектом на живом
    сервере, если сервер отвечает 400) — `toast.danger` с текстом ошибки, окно остаётся открытым,
    введённые значения на месте.
