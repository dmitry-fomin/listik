# Шаг 07. Запуск Codex из Claude

## Цель

Добавить минимальный Claude skill или wrapper, который запускает Codex для конкретной карточки,
не превращая Codex в отдельного оркестратора.

## Контракт wrapper

Вход: `task_id`, этап, модель (`terra`/`luna`), путь проекта и необязательный `--resume`.

Действия:

1. вызвать `listik show` и `listik context`;
2. проверить routing и claim/holder;
3. собрать короткий prompt с ролью (`s1` writer или `s2` critic), ограничениями и путями;
4. запустить `codex exec --cd <repo> --model <model> ... --json`;
5. сохранить session ID, последний ответ и exit status в journal;
6. при `--resume` использовать `codex exec resume <session>` и тот же task ID;
7. после завершения предложить/выполнить только предусмотренный `stage`, `needs-owner` или `done`.

На первом этапе wrapper не создаёт задачи, не вычисляет зависимости и не запускает другие
harnesses. Claude выбирает следующую задачу вручную или своим существующим skill.

## Критерии приёмки

* Один вызов запускает Codex в правильном repository/worktree и передаёт компактный контекст.
* Session ID можно найти в Listik и возобновить без потери задачи.
* Ошибка Codex записывается в journal и не закрывает карточку.
* s1/s2 не могут случайно выполнить кодинг без явного этапа/роли.
