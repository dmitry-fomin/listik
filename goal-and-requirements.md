# Listik

## Задача

Дать одному человеку и его агентам **одну очередь задач, один журнал работы и одну долговременную
память** по всем проектам — так, чтобы любая новая сессия восстанавливала контекст из карточки,
а не из переписки в чате.

## Проблема

Агентская работа теряется между сессиями. Два агента берут одну и ту же задачу. Вопрос человеку
тонет в чате, а через неделю никто не помнит, почему сделали именно так. Чтобы посмотреть, что
происходит, приходится выполнять команды в консоли — человеку там неуютно.

## Для кого

- **Человек** — смотрит доску в браузере, отвечает на вопросы, закрывает задачи, настраивает
  маршруты и репозитории.
- **Агент-исполнитель** (Claude Code, Codex, pi, dsh, opencode, devin, grok) — живёт в терминале,
  работает через CLI и MCP, берёт и передаёт карточки по протоколу этапов.

## Возможности

Что продукт уже делает:

- **Карточка задачи** — проект, тип, приоритет, статус, держатель с heartbeat, этап конвейера
  (`s1-spec → s2-review → s3-impl → s4-judge → done`), флаг «нужен человек», критерии приёмки,
  документы по путям, журнал и вердикты, рабочее дерево и ветка.
- **Конвейер и держатель** — переходы этапов с выдачей держателя, вердикт судьи `PASS/FAIL` и
  возврат в реализацию, поколения запуска и карантин записей «зомби»-процессов.
- **Зависимости как вычисление, а не поле** — жёсткие связи запрещают брать и закрывать, мягкие
  только информируют; готовность к работе, волны запуска, циклы.
- **Память и поиск** — гибридный поиск (FTS5 + векторы `bge-m3` через Ollama) по задачам,
  комментариям и документам; структурные чанки документов и компактный контекст этапа.
- **Маршруты запуска и харнессы** — таблица маршрутов (конвейеры `lp-<режим>` и маршруты роя),
  каталог харнессов с каналами моделей, автостарт исполнителя по маршруту.
- **Рой** — сам доводит волну задач проекта до конца: запускает, следит за деревьями, сливает
  готовые ветки барьером волны и гоняет интеграционные проверки; останавливается стоп-карточкой,
  когда слияние или проверки не сошлись.
- **Доска** — канбан по этапам, список, метрики, линия «нужен ты», карточка задачи, поиск, живое
  обновление по SSE; на телефоне — очередь задач и карточка только на чтение.
- **Три поверхности одного API** — CLI (он же клиент), HTTP и MCP. Агент работает и без поднятого
  сервера: CLI идёт в базу напрямую.
- **Общий Listik для команды** — серверный режим с владельцами задач и файлом `.listik.toml`
  в репозитории; рой на общем сервере не запускается.
- **Плагины Claude Code** — репозиторий сам маркетплейс: протокол задач, конвейер реализации,
  мосты к внешним харнессам, второе мнение, карта сервиса.
- **Установка, автозапуск и резервные копии** — одна команда установки, launchd/systemd,
  согласованный бэкап живой WAL-базы.

## Чего продукт не делает

Только то, что исключено решением:

- **Не строит учёток и прав.** Идентичность заявляется сама: один общий токен на сервер и
  `--owner`/`--actor`, которую участник пишет себе сам. Держатель карточки — строка, а не
  доказанный субъект; защита держится на договорённости, не на аутентификации.
- **Не заменяет git.** Всё, что делается с кодом, остаётся в ветках и деревьях проекта; Listik
  только помнит, чья это карточка и что с ней стало.
- **Не хранит файлы проектов.** Документы карточки — это путь (`spec_path`, `checklist_path`…) и
  загруженный текст; сервер не читает чужие файловые системы.
- **Не платит за модели и не выбирает их за вас.** Модельный вызов — только там, где он явно
  заказан (помощник, LLM-проходы роя, арбитр конфликта слияния) и только по ключам из конфига.

## Принципы

- **Один сервер, одна база, один API.** Источник истины — SQLite; `routes.json`, доска и CLI
  ничего не держат «второй правдой».
- **Стандартная библиотека.** Python 3.11+ без зависимостей, HTTP на `http.server`; установка не
  требует venv и пакетного менеджера.
- **Агент не должен вставать.** Мёртвый сервер не блокирует работу: CLI уходит в локальную базу,
  поиск без Ollama тихо остаётся лексическим.
- **Ошибка — один формат.** `code`/`message`/`hint` одинаковы в CLI, HTTP и локальном режиме:
  агент ветвится по коду, а не по тексту.
- **Решения живут в карточке.** Почему сделали именно так — в журнале задачи, а не в голове
  автора или истории чата.
