# Конвейер question-pipeline

Самый короткий пресет плагина: вопрос, один ответчик, ответ в карточку. Кода нет, коммита нет — ни кода,
ни бумаг, — приёмки нет. Модель ответчика выбираешь ты по сложности вопроса, правилом ниже. Пресет — выбор
автора 07.10.2026; обоснование — в
[ROLES.md, «Пресеты по типу задачи — выбор автора»](../../references/ROLES.md).

**Прочитай [pipeline-core.md](../../references/pipeline-core.md) целиком до первого действия** — но
применяй оттуда не всё: твоя роль, жёсткие правила (кроме всего, что про порции, приёмку и коммит), шаг 0
(журнал, карточка, эпик), журнал и раздел `## Listik` — да; этапы 1–4, треки, пакет диффа, приёмка и
пределы на порцию — нет. Карточка — скил [`listik:listik`](../../../listik/skills/listik/SKILL.md)
(`plugins/listik/skills/listik/SKILL.md`).

Скил запускается только по явному имени — маршрутом карточки Listik (`launch_route` или метка
`process:question-pipeline`) или человеком (`/feature-pipeline:question-pipeline`); по сходству задачи сам
его не подхватывай. Все команды — из корня основного дерева.

## Роль и выбор модели

| Этап | Кто | Модель и усилие | Первая строка отчёта |
| --- | --- | --- | --- |
| ответ | субагент `feature-pipeline:pipeline-answerer` | по правилу ниже; effort medium из frontmatter | `готово` или `не смог` |

Модель выбираешь **ты, до запуска**, по тексту вопроса:

| Модель | Когда | Вызов |
| --- | --- | --- |
| `haiku` | факт с одним очевидным местом в коде или документах: «где лежит», «какая команда», «какое значение» | **`model: haiku` в вызове** |
| `sonnet` | **по умолчанию**: объяснение по нескольким файлам, сравнение двух вариантов | **без `model`** — `sonnet` из frontmatter |
| `opus` | проектирование, «как лучше», размен между подсистемами, или автор попросил подумать | **`model: opus` в вызове** |

Неясно, какая строка подходит, — `sonnet`. Выбор — строкой журнала
`шаг <id>: отвечает <haiku|sonnet|opus> — <основание>`. В headless (`LISTIK_LAUNCHED_BY`) — то же правило,
автора не спрашиваешь.

Внешних каналов у скила нет, поэтому предполётной проверки тоже нет.

**Стоп-фактор.** Роль недоступна (харнесс не установлен или не залогинен, запуск упал, ответила не та модель) — конвейер стоит: журнал `стоп: <роль> — <харнесс> недоступен: <причина>`, `listik needs-owner <id> "<вопрос>"` и тот же вопрос в чат, и больше ничего. Запасного исполнителя нет: роль не подменяется ни другим харнессом, ни другой моделью, ни локальным субагентом, в headless тоже (`pipeline-core.md`, «Стоп-фактор»). Повтор того же харнесса и той же модели в той же роли — не подмена.

## Шаг 0 — карточка, журнал

- **карточка.** `show` и `claim --holder claude` — по «Шаг 0 — карточка» ядра; текст вопроса — из
  карточки (заголовок и описание) или из `$ARGUMENTS`. `$ARGUMENTS` пусто и карточки нет — спроси, что за
  вопрос. Карточка типа `epic` — стоп по «Эпик без писателя ТЗ — стоп» ядра: `needs-owner` с текстом оттуда,
  тот же вопрос в чат.
- **журнал** — `<steps>/<id>.journal.md` по ядру (без карточки — `<steps>/adhoc-<ГГГГ-ММ-ДД>-<слаг>.journal.md`),
  первой строкой — `шаг <id>: старт, пресет question-pipeline`.
- **дерево не заводится.** Вопрос ничего не пишет в код, поэтому ни `listik worktree`, ни отдельной ветки;
  проверка чистоты дерева ядра не применяется. В журнал — `дерево <абсолютный путь корня основного дерева>`
  (`git rev-parse --show-toplevel`), ответчику идёт этот путь.
- **файл ответа** — `<steps>/<id>.answer.md`, без карточки — `<steps>/adhoc-<ГГГГ-ММ-ДД>-<слаг>.answer.md`.
  Перед запуском — `ls <steps>/<id>.*` по правилу 7 «Имена бумаг и деревьев» ядра.

Heartbeat по карточке — по «Всегда» ядра, пока ответчик работает.

## Ответ — `pipeline-answerer`

`Agent` `feature-pipeline:pipeline-answerer` с моделью по правилу выше. В задаче — текст вопроса дословно,
абсолютный путь файла ответа и абсолютный путь дерева из журнала. Строки `Listik, карточка <id>` в задаче
нет: в карточку ответчик не пишет, её ведёшь ты. Формат файла и отчёта агент знает сам — не пересказывай.

- **`готово`** — проверь, что файл ответа есть и в нём есть строка `## Ответ`; дальше — «Ответ в карточку».
- **`не смог`** — один повтор **того же** субагента через `SendMessage` по его agent id, с его формулировкой
  причины дословно. `SendMessage` отказал или agent id потерян после `/clear` — **откат**: новый субагент с
  тем же текстом задачи и той же моделью, строка в журнал. Второй `не смог` — доклад автору: его причина
  дословно в чат и в `needs-owner`, карточка не закрывается.

## Ответ в карточку

Без карточки — раздел «Ответ» из файла отдаётся автору **дословно** в чат, и всё.

С карточкой — раздел «Ответ» берётся **из файла командой**, руками не переписывается и не пересказывается,
и уходит в журнал карточки ровно так:

```
ANS=$(sed -n '/^## Ответ/,/^## Основания/{/^## Основания/d;p;}' "<абс. путь <id>.answer.md>")
listik comment <id> "$(printf '%s\nфайл: %s' "$ANS" "<абс. путь <id>.answer.md>")" -k journal --actor agent:claude --harness claude
listik done <id> -r "ответ в журнале карточки" --actor agent:claude --harness claude
```

Этап карточки не двигаешь: `done` закрывает её с любого этапа. Ответ показываешь автору в чат той же
выдержкой. Строка журнала — `шаг <id>: готово, ответ в карточке`.

## Грабли пресета

| Симптом | Причина | Что делать |
| --- | --- | --- |
| На простой факт ответил Opus, на «как лучше» — Haiku | модель не выбрана по правилу или выбрана по привычке | правило таблицы до запуска, строка журнала `отвечает … — <основание>` |
| Выбран `sonnet`, а ответила другая модель | `model` передан там, где его нет | `sonnet` — без `model`, из frontmatter; `model` — только `haiku` и `opus` |
| В карточке пересказ, а не ответ | раздел «Ответ» переписан руками | только командой `sed` из файла, как в блоке выше |
| В комментарии буквальные `\n` вместо переносов | перенос записан в двойных кавычках без `printf` | ровно та форма, что в блоке выше |
| Оркестратор завёл дерево и ветку под вопрос | применён шаг 0 ядра целиком | дерево не заводится, путь — корень основного дерева |
