# listik-nghw — blocked_count доски по blocked_by, одно определение незакрытых блокеров

## Цель

Счётчик «Ждёт» на доске (`blocked_count` в `GET /api/board`) расходится с `/api/blocked`.
`store.board` считает его отдельным запросом: типы связей записаны литералом без
`resource-blocks`, а статусы блокеров берутся только из открытых задач самой доски. Поэтому
закрытый блокер и блокер из другого проекта считаются открытыми. Счётчик должен считаться
по тому же правилу, что `/api/blocked`, — по денормализованному `blocked_by` карточек.

Правило «незакрытое жёсткое ребро» (тип из `HARD_BLOCKERS`, блокер не `done`/`cancelled`,
отсутствующая задача считается открытой) сейчас пять раз повторено в `listik/deps.py`, и каждый
раз вся таблица `tasks` грузится в словарь. Нужен один общий помощник `open_hard_edges`
с LEFT JOIN, как уже сделано в `_waves`.

Словарь типов связей доски (`LINK_TYPES`) должен знать все типы из `DEP_TITLES`.

Приёмка карточки: `blocked_count` на доске равен числу задач из `/api/blocked` того же
проекта, в том числе с `resource-blocks` и с закрытыми блокерами. На это есть тест.

## Порции

- `a` — `store.board` считает `blocked_count` по `blocked_by` незакрытых карточек, отдельный
  запрос убран; в `LINK_TYPES` добавлены `conditional-blocks` и `resource-blocks`; в
  `docs/API.md` описан `blocked_count`. Тесты: счётчик равен `/api/blocked`; в серверном
  режиме он считается после фильтра владельца; словарь доски совпадает с `DEP_TITLES`.
- `b` — `deps.open_hard_edges` и константа плейсхолдеров `_HARD_MARKS`; через них
  переписаны `blockers`, `waiting_for`, `refresh_blocked_column`, `refresh_task`,
  `ready_tasks` (и плейсхолдеры в `cycles`); `_statuses` удалён. У `waiting_for` два
  изменения: у закрытой задачи он теперь пуст, а ровные идут по id, а не в порядке
  вставки. `docs/API.md` поправлен. Опирается на закоммиченную `a` только
  тестом доски в своих проверках.

## Вне шага

- `listik/documents.py` (`_dependencies`) перечисляет все жёсткие рёбра задачи, включая
  рёбра на закрытые блокеры, со статусом — это другое правило, помощник туда не подходит.
  Файл не трогаем.
- `deps._waves` / `apply_resource_blocks` / `apply_planned_blocks` работают со
  `SEMANTIC_HARD` и своими запросами — не трогаем.
- Серверный режим: доска считает только карточки, которые пропустил фильтр
  `X-Listik-Owner` («свои + без владельца»), а `/api/blocked` этот фильтр не применяет.
  Это расхождение задумано, шаг его не меняет.
- Если на одной паре задач стоят два жёстких типа, `blocked_tasks` покажет блокер дважды.
  Это поведение не меняется.
- Мок доски (`web/scripts/mock-api.mjs`) уже считает `blocked_count` по открытым задачам
  с блокерами — его не трогаем.
