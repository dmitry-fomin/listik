# listik-cvm8 — переходы этапов на доске берутся с сервера, тип перехода хранится в структурном поле события

Карточка: listik-cvm8 (bug, P2), родитель listik-hil0. Код сверен с коммитом `HEAD`.

## Цель

Доска подписывает переходы конвейера значениями, зашитыми в `web/src/lib/stages.ts` (`TRANSITIONS`).
Эти значения расходятся с сервером: сервер по умолчанию считает `s1-spec → s2-review` переходом
`handoff` (`listik/config.py`, `DEFAULTS["routing"]["transitions"]`), а доска — `sticky`. Кроме
того, доска не знает `sticky-return` и не учитывает переопределения проекта. Тип перехода в
событии `stage` доска достаёт регуляркой из `note`, поэтому он теряется, если агент передал свою
`--note`.

После шага:
- тип перехода, который сервер применил при `stage`, пишется в новое поле события
  `events.transition`. Поле хранится отдельно от `note` и не зависит от пользовательской заметки;
- `/api/meta` отдаёт общую таблицу маршрутизации (`routing`). Таблицу проекта (`routing_effective`)
  `projects[]` отдаёт и сейчас;
- доска берёт переходы из `routing_effective` проекта задачи, при его отсутствии — из
  `meta.routing`, а заголовок события читает из `event.transition`. В `stages.ts` из переходов
  остаётся только тип `Transition` с добавленным `sticky-return`.

Приёмка карточки: на доске с дефолтным config переход s1→s2 подписан handoff, а заголовок события
показывает тип перехода и при пользовательской `--note`.

## Порции (по порядку)

1. **a — сервер** (`listik-cvm8.a.md`, чек-лист `listik-cvm8.check-a.md`). Добавляет колонку
   `events.transition`: схема 14, мягкая миграция с досыпкой старых событий, alembic-ревизия `0012`.
   `next_stage` пишет в это поле тип перехода, `get_task` его отдаёт, `/api/meta` и локальный `meta`
   получают `routing`. Правятся `docs/API.md` и Python-тесты.
2. **b — доска** (`listik-cvm8.b.md`, чек-лист `listik-cvm8.check-b.md`). Порция опирается на
   закоммиченную a, то есть на контракт полей. Из `stages.ts` уходит таблица. Переходы считаются
   по `routing_effective`/`meta.routing` для рельсы, степпера и подсказки панели, заголовок события
   читается из `event.transition`. Мок получает поля сервера и флаг `--transitions`, добавляется
   новый скрипт `verify-transitions.mjs`.

## Как шаг закрывает приёмку

- «Переход s1→s2 подписан handoff при дефолтном config»: тесты порции a проверяют, что без
  config.toml `/api/meta` отдаёт `routing.transitions["s1-spec:s2-review"] == "handoff"`. Кейс
  `rail-all` из `verify-transitions.mjs` (порция b) проверяет, что рельса доски подписывает
  переход значением из `meta.routing`.
- «Тип перехода в заголовке события и при своей `--note`»: тест порции a — `stage` с
  пользовательской заметкой пишет `transition`. Кейс `event-titles` порции b — заголовок строится
  из `event.transition`, заметка при этом не разбирается.

## Вне шага

- CLI (`listik show`, `listik timeline`) не выводит `transition` отдельно. Заметка по умолчанию
  `этап -> X (kind)` остаётся прежней, поэтому в CLI тип виден как раньше.
- `/api/timeline` и блок активности метрик поле не получают.
- Доска перечитывает `/api/meta` только при загрузке. После смены маршрутизации проекта
  (`listik projects <slug> --routing`) подписи обновятся, когда страницу перезагрузят.
- Телефон (`PhoneTaskSheet.vue`) и дизайн-лист `web/src/sheet/fixtures.ts` переходов не
  показывают, их шаг не трогает.
