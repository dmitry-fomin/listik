# Бэкенд (`listik/`)

Пакет делает всё, что происходит между запросом и базой: семантику карточки, хранение и миграции,
поиск, маршруты, запуск исполнителей и надзор за роем. Его функции переиспользуют три поверхности —
HTTP (`server.py`), MCP (`mcp.py`) и прямой доступ из CLI (`client.local_call`), — поэтому правила
живут здесь, а не в поверхностях.

## Границы

Не знает о: доске (она говорит по HTTP и SSE), Node-рое (это отдельный процесс; здесь только его
надзор и git-слой наблюдателя), плагинах Claude Code (они говорят через CLI и MCP), файлах чужих
проектов, кроме явно выданных путей (`spec_path`, `worktree`, `.listik.toml`).

Может: читать `config.toml`, базу и каталог данных; звать внешние команды (харнессы, git, ollama) и
модели в перечисленных ниже точках.

## Подмодули

| Узел | Что это | Граница |
|---|---|---|
| `listik-card-core` | семантика карточки: этапы, держатель, зависимости, ошибки, области | база и статусы; ничего о поверхностях |
| `listik-storage` | схема, мягкая миграция, пути, конфиг | ничего о задачах |
| `listik-http-api` | HTTP API, раздача доски, SSE, `/mcp` по HTTP | самая широкая: зовёт всех |
| `listik-mcp` | MCP-инструменты `listik_*`, два транспорта | клиент, ядро, поиск |
| `listik-search-memory` | гибридный поиск, эмбеддинги, документы и чанки | ядро и ollama |
| `listik-routes-harnesses` | таблица маршрутов, каталог харнессов, справочник скилов | хранилище |
| `listik-launch` | запуск исполнителей, ограждение записи, рабочее дерево | ядро, маршруты, git |
| `listik-assistant` | помощник DeepSeek и голосовой ввод | ключи конфига и внешние API |
| `listik-install-ops` | установщик, автозапуск, резервные копии | система и файлы установки |

Разовый импорт из старого трекера (`import_writerllm.py`, `listik import-from-bd`) — внешний адаптер
поверх тех же функций записи; идемпотентен по `(source, project, external_ref)`, `--update` пишет
разницу в журнал.

Надзор за роем (`swarm_proc.py`, `swarm_watch.py`, `swarm_llm.py`) лежит в этом пакете, но описан
вместе с самим роем — `listik-swarm`.

## Инварианты пакета

- **Один путь записи.** Создание, правка, переход этапа, комментарий, связь — только через функции
  ядра; поверхности разбирают запрос и зовут их.
- **Циклов импортов нет, и это держится намеренно.** `errors` и `statuses` — листья; `fence` знает
  только `errors` и `store`; `launcher` не знает `server` и сообщает о событиях колбэком `notify`;
  `worktree` и `swarm_watch` не знают ни базы, ни сервера.
- **Новый модуль с собственной границей получает свою подспеку**, иначе его роль остаётся строкой
  в этой таблице.
