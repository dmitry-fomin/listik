# Доска (`web/`)

Веб-интерфейс к тому же API: канбан по этапам, список, метрики, линия «нужен ты», панель задачи,
поиск и живое обновление по SSE. Одна сборка (Vue 3 + TypeScript + Vite) кладётся в `web/dist`, и её
отдаёт сам сервер; на телефоне — только очередь задач и карточка на чтение.

## Решения

- **Один UI-кит и никаких CSS-фреймворков.** Все `Ui*`-компоненты — из `@zoloto585/facet`; свои
  стили пишутся только там, где в ките такого нет (колонки канбана, карточка, линия «нужен ты»).
  Дублировать разметку кита вручную запрещено, поэтому перед компонентом читается его
  purpose-комментарий, а не угадывается имя.
- **Доска только показывает.** Этап меняется из панели задачи или протоколом, перетаскивания карточек
  нет: движение по конвейеру — решение агента. Колонки собираются по серверной семантике `stage`, а
  не по статусу: закрытая на s4 карточка остаётся в колонке s4 с бейджем «закрыта».
- **Маршруты не зашиты в UI.** Порядок, роли и иконки берутся из `GET /api/routes` один раз за
  сессию; в `lib/routes.ts` только правила поверх них (выбор по умолчанию, доступность для типа
  задачи, группировка). Метки `harness:`/`process:` ставит сервер — доска их не считает.
- **Живое обновление не сбрасывает работу.** SSE с дебаунсом перечитывает доску, статистику и граф;
  открытая карточка при событии по ней подменяет данные без скелета и повторного монтирования, чтобы
  сохранить прокрутку и черновик поля. События по другим задачам открытую карточку не перечитывают.
- **Ключи провайдеров в браузер не попадают.** Помощник и голос идут через серверные эндпоинты;
  кнопки появляются только по `GET /api/assistant/status`.
- **Токен приходит ссылкой, но не остаётся в адресе:** найденный `?token=` запоминается в
  localStorage и убирается из строки — иначе он осядет в истории и закладках. Для SSE токен идёт
  параметром, потому что `EventSource` не умеет заголовки.
- **Телефон — режим чтения по решению.** При ширине до 767 px включительно доска, вкладки и фильтры не рендерятся вовсе:
  очередь и карточка без единого действия. Это не урезанная версия, а другой сценарий — «посмотреть,
  что происходит, с телефона».
- **Проверка — сценариями в браузере.** Юнит-тестов у доски нет: поведение проверяют скрипты
  `web/scripts/verify-*.mjs` (через CDP, на мок-API или на живом сервере) и `npm run smoke`. Поэтому
  мок-API повторяет формы ответов из `listik-api`, а у сценариев есть возврат 1 при провале.

## Граница

Может: HTTP API и SSE, собственный стейт и форматтеры, кит `facet`. Не может: ходить к провайдерам
моделей напрямую, читать базу, решать, кому можно брать задачу (это сервер). Контракт ответов и
эндпоинтов — `listik-api`.
