# MCP

`mcp.py` — сервер JSON-RPC 2.0 (протокол MCP), через который агенты работают с задачами
инструментами `listik_*`. Транспортов два, разбор сообщений общий: stdio (`listik mcp`) и HTTP
(`POST /mcp`, Bearer-токен, без SSE).

## Решения

- **stdio пишет в базу мимо сервера — и сам об этом сообщает.** Поэтому после успешного пишущего
  инструмента он в фоне зовёт `POST /api/notify`: иначе доска узнала бы о записи только после
  перезагрузки. Сервера нет, не ответил, задачи не знает — молча глотаем: инструмент обязан
  отвечать и без сервера.
- **`WRITE_TOOLS` — единственный список пишущих инструментов.** По нему решается, будить ли доску
  и проверять ли владельца в серверном режиме; чтения и ответы с `isError` доску не будят.
- **Прокси к общему серверу.** Если `.listik.toml` каталога агента ведёт на удалённый Listik,
  stdio-режим становится прокси: каждое сообщение уходит `POST <сервер>/mcp`, локальная база не
  трогается.
- **Ошибка инструмента — это не ошибка транспорта:** HTTP 200 и `result.isError: true`. Так же
  отвечает и отказ по правам (чужая задача).
- **Полнота важнее изящества:** у каждого эндпоинта карточки есть свой инструмент, и набор
  проверяется тестом на каждый инструмент — новый эндпоинт приходит вместе с инструментом.

## Граница

Может: клиент, конфиг, база, ограждение, поиск, ядро. Не может: HTTP-слой (иначе цикл), доска.
Набор инструментов и их схемы — в коде; контракт ответов — `listik-api`.
