# Рой

`bin/listik-swarm` + `swarm/` — отдельный процесс на Node (только stdlib), который доводит волну
задач проекта до конца без человека: тик за тиком смотрит, что можно запустить, запускает, следит за
деревьями, а когда никто не работает — сливает готовые ветки и гоняет интеграционные проверки.
Python-сторона (`listik/swarm_proc.py`, `swarm_watch.py`, `swarm_llm.py`) поднимает этот процесс из
сервера, даёт git-слой наблюдателя и единственную точку модельного вызова.

## Решения

- **Состояния между тиками нет.** Рой перечитывает настоящие карточки через CLI: упал — перезапустили,
  повторный тик видит реальность и не запускает дважды. Отсюда же — «предел откатов» считается по
  журналу карточки, а не по памяти процесса.
- **Только установленный CLI.** Рой говорит с Listik через `bin/listik … --json` и никогда не
  импортирует `listik/`: граница процесса, а не соглашение внутри пакета.
- **Решения — чистые функции.** `decide.mjs` не зовёт наружу ничего (время приходит аргументом),
  поэтому проверяется обычными тестами; исполнение отдельно — `run.mjs`.
- **Язык выбран по удобству разработки** (подтверждено автором), а не по архитектурной
  необходимости. Что код держит благодаря этому выбору: падение роя не роняет сервер и очередь, git и
  дочерние процессы не мешают HTTP-обслуживанию.
- **Барьер волны сливает по одной.** Когда никто не работает: rebase и `merge --ff-only` каждой
  готовой ветки по очереди, запись о слиянии в журнал карточки, разморозка задач, чей владелец только
  что слился, интеграционные команды проекта, уборка слитых деревьев. Не сошлось — открывается
  стоп-карточка `swarm:halt`, и проект не запускается дальше.
- **Модель вызывается только в известных местах:** арбитр конфликта при слиянии закрытой задачи
  (единственный модельный вызов в Node), проходы `plan`/`rescope` на Python — через одну
  функцию с двумя каналами (HTTP и внешняя команда), и решения jev через OpenRouter Decisions API
  (`swarm_llm.decide`: проверка итога арбитра и снятие рёбер). Все Python-вызовы живут в `swarm_llm`.
- **Знаки в журнале — протокол.** `рой: заморожена:`, `рой: вне write_scope:`, `рой: предел откатов`,
  `рой: не принята:` — совпадающие константы в Python и Node; расхождение ловится тестом, а не
  надеждой.
- **Нет интеграционных команд — нет слияния.** Незаданный или пустой `integration` в `swarm.json`
  останавливает проект стоп-карточкой: молча влить непроверенное рой не имеет права.

## Граница

Может: CLI Listik, git, дочерние процессы, модель через разрешённые точки. Не может: пакет `listik/`
импортом, базу напрямую, HTTP API (только через CLI). Python-сторона может: пути, конфиг, ядро (для
контекста и заметок) — но не решения роя.

Протокол карточки, на который опирается рой, — `listik-protocol`; настройки (`swarm.json`, команды
интеграции и арбитра) — в коде и `listik-api`.
