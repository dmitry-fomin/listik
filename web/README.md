# Listik — доска (web/)

Одностраничная админка трекера задач Listik: доска / список / метрики,
линия «Ты нужен», панель задачи, поиск и живое обновление через SSE.

Стек: Vue 3.5 + TypeScript + Vite. Единственная UI-библиотека — `@zoloto585/facet`
(все `Ui*`-компоненты оттуда). Никаких Tailwind/CSS-фреймворков: свои только те
стили, которых в ките нет (колонки канбана, карточка задачи, линия «нужен ты»).

## Запуск

```sh
cd ~/Projects/Listik/web
npm install

# API Listik (в другом терминале)
cd .. && listik serve

npm run dev        # http://127.0.0.1:5173, /api проксируется на 127.0.0.1:8787
npm run build      # → web/dist (сервер Listik отдаёт dist/index.html как SPA-фолбэк)
npm run preview    # посмотреть сборку
npm run typecheck  # vue-tsc --noEmit (strictTemplates включён в tsconfig.json)
```

Сборка кладётся в `web/dist` — её и отдаёт `listik serve` по адресу
`http://127.0.0.1:8787/` (ссылка с токеном печатается в `listik status`).

## Токен и адрес API

- Токен: параметр `?token=` в адресе (сервер сам печатает такую ссылку в
  `listik status`), либо `localStorage['listik.token']`, либо `VITE_LISTIK_TOKEN`.
  Найденный в адресе токен запоминается в localStorage, а параметр из строки адреса
  убирается — чтобы не оставался в истории и закладках. В запросах уходит заголовком
  `Authorization: Bearer`, а для SSE — параметром `?token=` (EventSource не умеет заголовки).
  Если токена нет или он неверный, приложение показывает форму ввода.
- Адрес API: `VITE_API_BASE`. По умолчанию **тот же origin**, под которым отдана
  страница: в прод сборку отдаёт сам сервер Listik, в dev `/api/*` проксируется на
  `http://127.0.0.1:8787` (см. `vite.config.ts`). Переменная нужна, только если API
  живёт на другом хосте/порту. Примеры — `.env.example`.

## Разработка без сервера

Заглушка API с теми же формами ответов, что в `docs/API.md`:

```sh
node scripts/mock-api.mjs 8788
VITE_API_BASE=http://127.0.0.1:8788 VITE_LISTIK_TOKEN=mock-token npm run dev
```

Аргумент `--fill=N` (после порта) добавляет к пяти базовым задачам ещё N сгенерированных
(`listik-fill-001`…) — удобно проверять пагинацию/сортировку списка. Без флага мок не меняется:
те же 5 задач и те же ответы `/api/board`, `/api/meta`, `/api/ready`, `/api/blocked`.

Флаг `--links` добавляет срез блока «Связи» с краевыми случаями: закрытая связь (есть в
`dependencies`, но не в `blocked_by`), один и тот же адресат двумя строками `deps`, задача
другого проекта, id в другом регистре, ссылка на удалённую задачу, взаимные ссылки A↔B и
`listik-links-slow` — карточка, которую `--slow-ms=N` отдаёт с задержкой (гонка двух открытий).
Проверка переходов по этим ссылкам — `scripts/verify-deps-links.mjs`.

Служебные ручки для скриптов проверки (в docs/API.md их нет — это не контракт, а управление
моком, как `__token`): `POST /__event` рассылает кадр в открытые `/api/stream` (тело
`{kind, payload, patch?, comment?}`; `patch`/`comment` сперва правят заглушку, чтобы
запись была видна в панели), а `GET /__requests` и `POST /__requests/reset` считают
чтения карточек `GET /api/tasks/{id}`.

## Смоук-тест живой страницы

Открывает приложение в headless Chrome и проверяет, что все четыре вида
рендерятся, панель задачи открывается нужной ширины, а в консоли нет исключений:

```sh
npm run dev                       # или npm run preview
npm run smoke -- http://localhost:5173/
```

Второй аргумент — ширина окна (по умолчанию 1440). Ширина < 768 включает эмуляцию
телефона (360×740, `Emulation.setDeviceMetricsOverride`) вместо реального окна Chrome; отчёт
на любой ширине содержит блок `phone`, который считает только видимые элементы
(`offsetParent !== null`) — колонки/бейджи, скрытые медиа-запросами, в него не попадают.

## Создание задачи

Кнопка **«Новая задача»** на доске (`BoardView` → `emit('create')` → `App.vue`) открывает
`NewTaskModal`: тип (эпик · ТЗ / задача / баг), проект, приоритет (P0 доступен только багу),
заголовок, описание · ТЗ, критерии приёмки, путь к ТЗ (`spec_path`) и блок «Маршрут» — общий
`RoutePicker`. Записи маршрутов (пресеты конвейера и прямые харнессы, их порядок, роли и иконки)
в UI не зашиты: их отдаёт сервер — `GET /api/routes`, файл `routes.json`; доска грузит их один раз
за сессию. В `lib/routes.ts` только правила поверх этих данных: выбор по умолчанию, доступность по
типу задачи (эпику нужна запись с `roles.spec`), группировка для матрицы и поиск по ключу.
В `POST /api/tasks`
уходят `title, project, type, priority, description, acceptance, spec_path, route, actor`;
метки `harness:<x>`/`process:<y>` по ключу маршрута ставит сервер (`routes.labels_for`) —
доска их не считает, они только для человека и поиска, полей
`harness`/`skill` у карточки нет и после шага 04, автоматической раздачи задач по этим меткам
нет. Список маршрутов (`routes.json`) не связан с `routing` проекта на сервере: кто реально допущен
до этапа, решает сервер (`ready --harness`, отказ причиной в `claim`).

## Помощник DeepSeek у полей

У каждого текстового поля формы (заголовок, описание · ТЗ, приёмка, `spec_path`) есть
`AssistantField`: при наведении на поле поверх него появляется полупрозрачная кнопка, по клику
открывается поповер с предложением — переписанный текст поля, критерии для приёмки, оценка
когнитивной сложности и маршрут из `routes.json`. Применяется только по подтверждению: у текста,
критериев и маршрута отдельные кнопки, маршрут проходит те же правила доступности (`lib/routes.ts`), что
клик по записи в `RoutePicker`.

Ключ DeepSeek в браузер не попадает. Доска ходит в серверные `GET /api/assistant/status` (узнать,
настроен ли помощник) и `POST /api/assistant/suggest` (сам запрос); `api_key` живёт в
`config.toml`, раздел `[assistant]` (см. README репозитория). Пока `enabled=false` — ключа нет
или запрос статуса не удался, — кнопок нет вовсе; ошибку самого запроса (таймаут, отказ
DeepSeek) показывает панель помощника и не роняет доску.

## Голосовой ввод задачи

Кнопка «Голосом» на доске (`BoardView`) и круглый кружок над очередью на телефоне
(`PhoneQueue`) появляются, только когда `GET /api/assistant/status` отдаёт `voice: true`
(флаг тянется один раз за сессию); иначе в DOM ничего нет. Запись — через `MediaRecorder`,
аудио уходит в `POST /api/assistant/transcribe`, расшифровка — в `POST /api/assistant/draft`.
Дальше черновик либо создаёт задачу одной кнопкой, либо предзаполняет «Новую задачу»;
создание и открытие формы — тот же код `App.vue`, что у обычной кнопки. Ключи
Deepgram/DeepSeek в браузер не попадают — они живут в `config.toml` на сервере; контракт
ручек и поле `voice` — `docs/API.md`. Отказ микрофона, тишина и падение провайдера
показываются текстом в панели записи и не роняют доску.

Телефон (`VoiceCapture variant="phone"`): короткое нажатие на кружок открывает лист снизу
и оставляет запись идти (закончить — «Готово» или повторный тап), удержание заканчивает
запись на отпускании, а `pointercancel`, «Отмена» и закрытие листа отменяют её — ни одного
запроса, дорожки микрофона погашены. Лист — `UiDrawer side="bottom"`.

Проверка — на моке `mock-api --voice` и собранном `dist`:

```sh
npm run build
node scripts/verify-voice.mjs
```

Скрипт гоняет десктопные и телефонные (эмуляция 390×844) сценарии со стабом микрофона и
счётчиками `GET /__requests`; код возврата 1 при провале.

## Слой зависимостей

Сервер считает «можно ли брать задачу» по графу связей, а не по флагу в базе
(подробно — `docs/API.md`, раздел «Зависимости»). Доска показывает это так:

- **чип «можно брать» в тулбаре** — `board.ready`: задачи без незакрытых жёстких
  блокеров и без держателя; клик по чипу фильтрует текущий вид по этому признаку;
  в карточке видно «за ней ждут N»;
- **карточка задачи** — счётчики «ждёт N» и «её ждут N» иконками (`CountGlyph`:
  замок `warning`, ключ `accent`; в подсказке замка — ID блокеров); данные берутся
  из `depsSummary` (срез из `/api/ready` + `/api/blocked`), а не из запроса на
  каждую карточку;
- **колонка доски** — держатели её задач по харнессу и точки здоровья в шапке
  (`BoardColumn`), без отдельного счётчика по зависимостям;
- **панель задачи** — подсказка под рядом действий («взять нельзя: …»/«можно брать
  прямо сейчас», собранная из `deps_state.reasons`) рядом с `UiSplitButton` «Взять в
  работу»: главная кнопка кликабельна только когда `deps_state.ready`, а меню
  сплит-кнопки несёт «Взять всё равно (обход блокеров)» (`claim` с `force: true` под
  `UiConfirmDialog tone="danger"`, доступно только для заблокированной свободной
  задачи), «Закрыть с результатом…» и «Добавить связь…»; рядом с «Освободить» —
  кнопка «Удалить» (`DELETE /api/tasks/{id}` под `UiConfirmDialog tone="danger"`:
  задача пропадает вместе с комментариями, связями и историей; закрытие с
  результатом историю сохраняет); сетка «Связи» — карточки
  «Ждёт завершения», «Ждут её завершения», «Незакрытые дети», родитель, `soft_links`
  строкой «связано, не блокирует» и дерево связей по кнопке; «Холодный старт» —
  таблица из 7 строк (`spec_path`, чек-лист/`acceptance`, журнал/решение, worktree,
  блокеры, `comment -k journal`, `comment -k review`) с бейджем «N из 7». Строка
  «worktree · branch» красится по состоянию дерева (справочник `WORKTREE_STATES` в
  `src/lib/dictionaries.ts`): зелёная с путём и веткой, когда дерево/ветка указаны;
  жёлтая «работа в main»/«работа в master» — при маркере основной ветки
  (`listik set <id> worktree=main`, см. `docs/API.md`), и жёлтое состояние считается
  заполненным полем в счётчике; красная «рабочее дерево не указано» — когда ни
  дерева, ни ветки нет (тогда и бейдж счётчика красный);
- **вид «Список»** — колонки «Ждёт» и «Её ждут» (включаются в `UiColumnSetting`,
  по умолчанию видны), фильтр «все / можно брать / заблокированные» (он же есть в
  фильтр-баре списка и чипами тулбара);
- **вид «Метрики»** — `board.blocked_count`, число готовых к работе и циклы в
  зависимостях (циклы, если есть, показываются `UiAlert` и на самой доске).

Циклы (`board.cycles`) в норме пусты; непустой список означает, что задачи ждут друг
друга по кругу и сами не разблокируются — это ошибка в связях, её надо править.

## Репозитории на доске

Доска собирается по проектам из таблицы `projects`, поэтому «что показывает канбан»
настраивается там же: кнопка **«Репозитории»** в шапке открывает `ProjectSettings`
(`POST/GET/PATCH/DELETE /api/projects`).

- **добавить** — путь к каталогу, slug подставляется из имени каталога (можно задать свой,
  чтобы проект лёг в категорию: `Zoloto585/my-repo`); git remote и ветка подтягиваются сами;
- **скрыть с доски** — тумблер в строке: проект уходит из колонок и фильтров, задачи
  остаются в истории и в поиске;
- **убрать совсем** — кнопка удаления с подтверждением; проект с задачами сервер без
  `force` не удалит, и интерфейс предлагает второй шаг — «удалить вместе с задачами».

То же самое из терминала: `listik projects`, `--add <путь>`, `--archive`, `--unarchive`,
`--remove [--force]`.

## Проверка живой страницы

Кроме `npm run smoke` (вкладки, инбокс, тулбар, панель задачи, консоль) есть точечный
сценарий через CDP на настоящем API:

```sh
node scripts/verify-projects.mjs "http://localhost:5173/?token=<токен>" /tmp/папка listik-check-repo
```

Сценарий ходит в настоящий API и трогает базу: добавляет, скрывает и удаляет
репозиторий с временным slug — запускайте его на временном каталоге.

Кнопка удаления задачи в панели проверяется на моке (ничего в боевой базе не
трогает, сам поднимает `mock-api` и статику собранного `dist`):

```sh
npx vite build --configLoader runner
node scripts/verify-task-delete.mjs
```

Сценарий открывает карточку, жмёт «Удалить», отменяет — задача на месте;
подтверждает — панель закрывается, карточки на доске нет; кадр SSE
`action=deleted` по открытой задаче закрывает панель сам.

Переходы по ссылкам блока «Связи» панели задачи проверяются отдельным сценарием на моке
(ничего не трогает, сам поднимает `mock-api --links` и статику собранного `dist`):

```sh
npx vite build --configLoader runner
node scripts/verify-deps-links.mjs
```

Отчёт — JSON со списком сценариев (закрытая связь, чужой проект, регистр id, удалённая
задача, повторный клик, взаимные ссылки, гонка загрузки, чужое дерево связей); код
возврата 1, если хоть один не прошёл.

Реакция открытой карточки на события доски проверяется так же, на своём моке (кадр шлёт
ручка `POST /__event`, чтения карточки считает `GET /__requests`):

```sh
node scripts/verify-detail-sse.mjs
```

Сценарий ждёт, что событие по открытой задаче перечитывает её — в панели появляется новая
запись журнала и новый заголовок — не сбрасывая прокрутку, черновик поля журнала и не
показывая скелет; а событие по чужой задаче открытую карточку не перечитывает, хотя доска
обновляется (это проверяется отдельно, чтобы «ноль чтений» не был тихим пропуском кадра).

Три состояния строки «worktree · branch» блока «Холодный старт» проверяются так же —
на моке `mock-api --cold` (четыре задачи: дерево с веткой, `main`, `master`, пусто) и
собранном `dist`:

```sh
npx vite build --configLoader runner
node scripts/verify-cold-start.mjs
```

Сценарии проверяют цвет и текст строки, счётчик «N из 7» (жёлтое состояние считается
заполненным) и что точка-статус — `UiStatusPill` кита; код возврата 1 при провале.

Markdown-вывод описания карточки проверяется на моке `mock-api --markdown` (карточка
`listik-markdown-case` с заголовком, списками, инлайн-кодом, блоком кода, ссылкой и
HTML-строкой) и собранном `dist`:

```sh
npx vite build --configLoader runner
node scripts/verify-markdown.mjs
```

Сценарий ищет секцию «Описание · ТЗ» и все кейсы — от неё: форматирование заголовка,
списков, кода и ссылки, отсутствие сырой разметки в видимом тексте и экранирование HTML
(нет элемента `script`, диалог не всплывал); код возврата 1 при провале.

## Телефон (< 768 px)

Ниже порога 768 px (планшет остаётся 768–1023 px — тот же `MobileTaskList`/`.listik-mobile-queue`,
что и раньше) шапка теряет кнопку «Репозитории», доска/вкладки/инбокс/тулбар со всеми чипами и
фильтрами не рендерятся вовсе — вместо них единственная секция `PhoneQueue`: фильтр «проект» +
поиск и очередь задач по 20 (`GET /api/tasks?limit&offset&order=updated`, «Показать ещё» грузит
следующую страницу тем же запросом со сдвигом `offset`). Строка очереди — `MobileTaskRow`; клик
по ней открывает карточку задачи.

Карточка задачи на телефоне (`PhoneTaskSheet`) — **только чтение**: держатель и heartbeat,
критерии приёмки, блокеры (текстом, без ссылок на другие задачи), последний комментарий с
`kind ∈ {review, verdict}`, журнал — последние 20 комментариев любого вида (без событий),
новые сверху. Никаких действий: ни claim/comment/needs-owner/heartbeat/stage/release/done, ни
полей ввода, ни кнопок копирования/перехода к другим задачам — единственная кнопка компонента
(«Повторить») есть только при ошибке загрузки. Закрытие карточки (крестик/Escape/фон) возвращает
к тому же месту списка — `PhoneQueue` не перемонтируется. Планшет (768–1023 px) и десктоп
продолжают открывать полный `TaskDrawer`.

Порог переключения — 767 px (`lib/viewport.ts`, `useIsPhone`), совпадает с CSS-медиа-запросом
`@media (max-width: 767px)`. Телефон не делает запросов доски/готовности/заблокированных/
статистики/таймлайна/метрик/health — только `/api/tasks` (список), `/api/meta` и
`GET /api/tasks/{id}` при открытии карточки.

Проверка: `node scripts/mock-api.mjs 8788 --fill=50` (много задач для очереди и пагинации), затем
`npm run smoke -- http://localhost:5177/ 360` — эмулирует телефон 360×740 и отчёт содержит блок
`phone` (очередь, «Показать ещё», число запросов) и `phone.sheet` (открытие карточки по клику,
число видимых секций, 0 кнопок действий, 0 полей ввода, число записей ленты, восстановление
прокрутки после закрытия).

## Особенности

- **Тёмная тема по умолчанию** (`data-theme="dark"` ставится до монтирования),
  светлая переключается кнопкой в шапке. Цветовая гамма (`useColorScheme()` из кита) —
  в «Настройках», вкладка «Оформление».
- **Доска только показывает** — этап меняется исключительно из панели задачи
  (кнопка «Следующий этап»); перетаскивания карточек между колонками нет.
  Раскладка одна — по этапам конвейера; все задачи в любых срезах — во вкладке «Список».
  Колонки резиновые (не уже `--listik-col-min`); клик по заголовку сворачивает колонку
  в узкую рельсу, остальные расширяются; какие свёрнуты — помнит localStorage.
  «Готово» — всегда рельса со счётчиком за 7 дней, клик открывает «Список» с фильтром
  статуса `done`.
  Колонки собираются по серверной семантике `stage`, а не по статусу: закрытая на s4
  задача остаётся в колонке s4 с бейджем «закрыта»/«отменена», а открытая задача со
  `stage = done` (прошла `stage` после s4, но не закрыта) лежит в «Заведена» с
  бейджем «после s4».
- **Панель задачи** — `UiDrawer`; у кита размеры только `sm|md|lg` (560px у `lg`),
  ширина ~720px задана правилом `body .ui-drawer-backdrop.ui-drawer-backdrop--right
  .ui-drawer.ui-drawer--right.ui-drawer--lg` в `src/assets/app.css`: собственное
  правило кита — `.ui-drawer--right.ui-drawer--lg[data-v-…]` (специфичность 0,4,0),
  и поднять выше можно только большей специфичностью, без `!important`.
- **Живое обновление по SSE** — `/api/stream` с дебаунсом 500 мс перечитывает доску,
  статистику и граф зависимостей. Открытая карточка при этом не сбрасывается: если
  событие пришло по той задаче, что сейчас в панели, её `detail` подменяется готовым
  ответом — без скелета, обнуления и повторного монтирования, поэтому прокрутка,
  черновик поля журнала и открытые формы остаются на месте. События по другим задачам
  открытую карточку не перечитывают.
- **Смена маршрута в панели** — секция «Маршрут запуска» показывает ту же матрицу,
  что «Новая задача» (`RoutePicker`: иконки уровня, роли, прямые харнессы). Пока
  сервер отдаёт `route_editable = true` (задача заведена: без этапа, держателя и
  запущенного процесса), клик по записи сразу шлёт `PATCH` с полем `route`; пункт
  «без маршрута» снимает его (`route: ''`). Метки `harness:<…>`/`process:<…>`
  переписывает сервер (старые снимает, метки нового ставит, остальные метки задачи
  сохраняет) — доска их не считает. У начатой задачи редактор не показывается —
  там та же секция под заголовком «Автостарт» с одним прочитанным маршрутом
  (сервер всё равно ответил бы `400`).
- **Ответ автору из панели снимает флаг** — строка ввода секции «Журнал и вердикты»
  с видом «ответ» уходит в `emit('needsOwner', {id, value:false, note})` →
  `store.answerQuestion`, тот же запрос `POST …/needs-owner`, что снимает `needs_owner`
  и пишет комментарий `kind=answer`; кнопка «Ответить» инбокса «нужен ты» открывает
  панель и сразу ставит вид «ответ» с фокусом в это же поле (`focusAnswer`).
- **Фильтры**: проект и поиск — кнопки в шапке (`ProjectPicker`, палитра `SearchPanel`)
  и действуют на все виды; чипы здоровья/зависимостей (`BoardToolbar`) и «Ты нужен» —
  только на доске.
  Фильтр-бар (`TaskFilters`/`UiFilterBar`) — только в виде «Список»: статус, этап,
  исполнитель, тип, здоровье, зависимости и диапазон дат обновления; какие из них
  сервер не умеет (`нужен ты`, здоровье, тип, исполнитель, диапазон дат), применяются
  на клиенте, статус и этап уходят в запрос.
- **`pnpm`/`npm` про `@zoloto585/facet`:** пакет source-only, поэтому `vue-tsc`
  типизирует его исходники. В `UiSectionNav.vue` кита есть неиспользуемый импорт
  `ref`, который валит `npm run typecheck` из-за `noUnusedLocals`; `scripts/patch-facet.mjs`
  (postinstall) убирает его — идемпотентно и только внутри `node_modules` этого проекта.
